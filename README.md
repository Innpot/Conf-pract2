# Конфигурационное управление · Практическая работа № 2

Вариант **20**, ИКБО-18-25. Консольный инструмент читает индекс пакетов
Ubuntu, строит граф обязательных зависимостей и выводит PlantUML. Для
защиты есть автономные примеры с общим потомком, циклом и фильтром.

## Запуск

Нужен Python 3.10+. Сторонних Python-библиотек и сборки нет.

~~~sh
./run.sh --config examples/diamond.ini
./run.sh --config examples/cycle.ini --order
python -m unittest discover -s tests -v
~~~

В Windows: `run.bat --config examples/diamond.ini`. Универсальный запуск
из корня: `python -m src.main`. Скрипты учитывают переменную `PYTHON` и
переходят в корень репозитория. `--help` показывает параметры CLI.

| Ключ секции `[graph]` | Назначение |
| --- | --- |
| `package` | Корневой пакет: имя apt или прописные латинские буквы в тестовом режиме |
| `repository` | HTTP(S) URL индекса Packages либо путь к UTF-8 файлу относительно INI |
| `test_mode` | `true`: локальный тестовый граф; `false`: индекс Ubuntu |
| `ascii_tree` | `true`: допечатать ASCII-дерево после PlantUML |
| `exclude` | Регистрозависимая подстрока имени, пустое значение отключает фильтр |

Без `--config` используется `examples/ubuntu.ini`. `--plantuml-only`
оставляет на stdout только PlantUML, пригодный для записи в файл.
`--order` переключает вывод на порядок обхода, включая корень.
Предупреждения и ошибки идут в stderr. Ошибки конфигурации, чтения или
отсутствующего корня дают ненулевой код завершения. На этапе 1
демонстрация ошибок всех параметров доступна через тесты конфигурации.

## Демонстрация

| INI | Случай | `--order` |
| --- | --- | --- |
| `examples/diamond.ini` | A зависит от B и C, обе ветви ведут в D | D, B, C, A |
| `examples/cycle.ini` | X → Y → X и отдельная ветвь Z | Y, Z, X; предупреждение о цикле |
| `examples/filter.ini` | M → N → P, ветвь SKIP → K исключена | P, N, M |

В тестовом графе строка `A: B C` объявляет зависимости A от B и C;
`B:` объявляет лист. Все вершины надо объявить, порядок строк
произвольный. Пустые строки и комментарии с `#` игнорируются.

Три примера с реальными пакетами Ubuntu 24.04 Noble (main, amd64):

~~~sh
./run.sh --config examples/ubuntu.ini --plantuml-only > hello.puml
./run.sh --config examples/ubuntu-sed.ini --plantuml-only > sed.puml
./run.sh --config examples/ubuntu-jq.ini --plantuml-only > jq.puml
~~~

Любой из файлов можно открыть в редакторе PlantUML или локально собрать
через `plantuml -tsvg hello.puml sed.puml jq.puml`. Без
`--plantuml-only` настройки для `sed` и `jq` также печатают ASCII-дерево.
В нём повторный узел отмечается `[see above]`, а отсутствующий в индексе
— `[missing]`. Стрелки идут от пакета к его зависимости.

## Алгоритм и сравнение с APT

Индекс может быть обычным Packages, GZIP или XZ. Программа разбирает
deb822, берёт `Pre-Depends` и `Depends`, убирает версии и квалификаторы
архитектуры, сохраняет имена всех альтернатив и удаляет дубликаты.
Ожидается один индекс выбранной архитектуры и компонента с одной
записью на имя. Программа строит граф объявленных связей: она не
разрешает виртуальные пакеты через `Provides` и не выбирает версию.

DFS работает на явном стеке итераторов. При входе вершина попадает в
граф и множество активных; при выходе она удаляется из активных и
записывается в постпорядок. Ребро в активную вершину замыкает цикл и
сохраняется в графе. В ациклическом графе каждая зависимость стоит
раньше пакета, который её требует; при цикле строгого порядка нет.
Для графа из V вершин и E рёбер обход занимает O(V + E) без учёта
скачивания и разбора индекса.

На Ubuntu 24.04 выполните:

~~~sh
sh scripts/compare-apt.sh hello sed jq
~~~

Скрипт сопоставляет DFS с последовательностью `Inst` из
`apt-get -s --no-install-recommends install`, а граф — со штатным
`apt-cache dotty`. APT читает тот же индекс, использует пустой список
установленных пакетов и не устанавливает пакеты. Этот шаг также
запускается в GitHub Actions. APT выбирает одну подходящую альтернативу,
разрешает виртуальные пакеты и учитывает ограничения версий, конфликты
и системные правила. Поэтому порядок `Inst` и множество его пакетов
могут отличаться от постпорядка DFS. `dotty` рисует зависимости и
представляет типы пакетов и рёбер средствами Graphviz, а PlantUML
показывает только два обязательных поля и сохраняет обратные рёбра.

Справка: [apt-get](https://manpages.ubuntu.com/manpages/noble/man8/apt-get.8.html),
[apt-cache](https://manpages.ubuntu.com/manpages/noble/man8/apt-cache.8.html),
[PlantUML](https://plantuml.com/component-diagram).

## Структура

| Файл | Ответственность |
| --- | --- |
| `src/config.py` | `load_config`: чтение и проверка INI |
| `src/apt_index.py` | `fetch_index`: скачивание; `decode_index`: распаковка; `parse_index`: разбор |
| `src/fixture.py` | `load_fixture` и `read_fixture`: разбор локального графа |
| `src/graph.py` | `build_graph`: DFS, обратные рёбра и постпорядок |
| `src/visualize.py` | `plantuml` и `ascii_tree`: текстовые форматы |
| `src/main.py` | `main`: CLI, диагностика и выбор формата |
| `tests/`, `examples/`, `scripts/` | Тесты, конфигурации для защиты и сравнение с APT |

История разработки: `git log --reverse --format=%s`. Пять коммитов
`feat(config)`, `feat(apt)`, `feat(graph)`, `feat(order)` и
`feat(viz)` соответствуют этапам работы.
